## [v0.1.0] - 2026-10-27

### Highlights

- Postman collections for every AAuth (draft-11) access mode, generated by pidl from the AAuth protocol document in agent-protocols, so the requests, order and checks match the AAuth walkthrough step for step
- One Docker Compose file runs the aauth-go sandbox and, as an optional second part, the Petstore as an AAuth resource, with Newman runs of both collections: 21 requests and 98 assertions for the access modes, 10 requests and 47 assertions for the Petstore
- `make demo` shows a real run beside the AAuth walkthrough: every message the sandbox saw, matched to the protocol's steps, with tokens decoded and raw values masked

### Added

- Signed AAuth collection: agent identity, resource-managed access (two-party), person identity, PS authorization (three-party) and federated authorization (four-party), as the sandbox's demo resources perform them, with the sandbox environment ([`adb8447`](https://github.com/aistandardsio/aauth-postman/commit/adb8447))
- Mock collection that carries the walkthrough's example responses, for reading the flows on a Postman mock server ([`b4945b9`](https://github.com/aistandardsio/aauth-postman/commit/b4945b9))
- Petstore collection: browsing the pets with the agent's identity, and placing an order that is challenged for a person token, then an auth token, before it goes through ([`a7e5893`](https://github.com/aistandardsio/aauth-postman/commit/a7e5893))
- PIDL documents the collections are generated from: `pidl/aauth_sandbox.json` and `pidl/aauth_petstore.json`, each extending the AAuth document from agent-protocols ([`1c9ac60`](https://github.com/aistandardsio/aauth-postman/commit/1c9ac60))
- Signed requests tell the sandbox's signing helper how to sign with the `Signature-Key` header: a saved token by its `typ`, the helper's own agent token, enrollment or a header web key ([`17d4f01`](https://github.com/aistandardsio/aauth-postman/commit/17d4f01))
- `make demo`, `make demo-omniagent` and `make demo-page` capture a run against the sandbox and write `demo/live.html`, with the binding in `bindings/sandbox-petstore.binding.json` ([`f01a6ff`](https://github.com/aistandardsio/aauth-postman/commit/f01a6ff))

### Documentation

- README with the Docker quick start and the setup's two parts ([`58032bb`](https://github.com/aistandardsio/aauth-postman/commit/58032bb))
- Guide to running the collections against the sandbox: Docker or a local sandbox, how signing works, mock mode and regenerating ([`78c839b`](https://github.com/aistandardsio/aauth-postman/commit/78c839b))
- Interop testing runbook, for people and AI agents, for testing an agent, resource or server of your own against the sandbox ([`61cb922`](https://github.com/aistandardsio/aauth-postman/commit/61cb922))
- Documentation site at aistandards.io/aauth-postman, with the guides in `docs/guides/` and a new guide to the Petstore demos ([`b4ecc8e`](https://github.com/aistandardsio/aauth-postman/commit/b4ecc8e))

### Build

- `make generate` writes the collections and environments from the PIDL documents and `targets.json` ([`b3ae696`](https://github.com/aistandardsio/aauth-postman/commit/b3ae696))
- The signing helper's URL is an environment variable, `signer_url`, so a run can choose it ([`fe65181`](https://github.com/aistandardsio/aauth-postman/commit/fe65181))
- Docker Compose runs the sandbox with every role and the signing helper, on host ports set by `SIGNER_PORT` and `SANDBOX_HTTPS_PORT`, and the `test` profile runs the AAuth collection with Newman ([`e5560b0`](https://github.com/aistandardsio/aauth-postman/commit/e5560b0))
- The `petstore` profile runs the Petstore as an AAuth resource behind the sandbox, and its collection with Newman ([`fac6e40`](https://github.com/aistandardsio/aauth-postman/commit/fac6e40))
- The `omniagent` service chats with the Petstore as its agent ([`ef6afcb`](https://github.com/aistandardsio/aauth-postman/commit/ef6afcb))
- Sibling checkouts are located by org, in the `~/go/src/github.com/<org>/<repo>` layout, or set with `AAUTH_GO_DIR`, `PETSTORE_DIR` and `OMNIAGENT_DIR` ([`3acbeae`](https://github.com/aistandardsio/aauth-postman/commit/3acbeae))
- The make targets run pidl v0.10.0 with `go run` and fetch the AAuth document from the agent-protocols v0.9.0 release, so they need no checkouts; `PIDL`, `PIDL_VERSION`, `AAUTH_PROTOCOLS_VERSION`, `AAUTH_DOC` and `CURL` select other versions or local copies ([`ab27a20`](https://github.com/aistandardsio/aauth-postman/commit/ab27a20))
