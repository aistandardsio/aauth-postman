# AAuth Postman Collection

Postman collections for [AAuth](https://datatracker.ietf.org/doc/draft-hardt-oauth-aauth-protocol/) (draft-hardt-oauth-aauth-protocol-11): every access mode as a folder of requests you can send, from agent identity to federated authorization, with values passed from each response to the next request and checks on every response.

## How It Works

- **Generated, not hand-written.** The collection is generated by [PIDL](https://github.com/grokify/pidl) from the same AAuth protocol description that drives the PIDL walkthrough viewer, so the requests, order and checks match the walkthrough step for step. Edit the protocol description, not the collection.
- **Postman plays the agent.** The agent provider, resource, person server and access server are real servers: the [AAuth sandbox](https://github.com/aauth-dev/aauth-go) from aauth-go runs them all, on a laptop, in Docker or on Kubernetes.
- **Signing happens outside Postman.** Every AAuth request carries an HTTP message signature (RFC 9421). Requests go through the sandbox's signing helper, which signs them with the agent's key and forwards them.

## Layout

| Path | Contents |
|------|----------|
| `collections/` | Generated collections: signed (against the sandbox) and mock (saved example responses) |
| `environments/` | Generated environments: local sandbox, Docker, minikube and Postman mock server |
| `docs/` | Setup and workshop guides |

## Quick Start

With Docker, and an aauth-go checkout next to this repository (`../aauth-go`) until the sandbox image is published:

```bash
docker compose up -d --wait                     # the AAuth sandbox: every role plus the signing helper
docker compose --profile test run --rm newman   # run every access mode with Newman
```

Or `make test-docker`, which does both.

In Postman, import `collections/aauth.postman_collection.json` and `environments/sandbox.postman_environment.json`, select the environment, and run a folder. Postman talks only to the signing helper at `http://127.0.0.1:8099`, so no hosts entries or certificates are needed.

Without Docker, run the sandbox from aauth-go with `go run ./cmd/aauth-sandbox serve`; see [docs/setup.md](docs/setup.md).

## Exploring Without Running Anything

Import the mock collection and create a Postman mock server from it. Each request returns the example response from the AAuth walkthrough. The mock mode signs nothing and checks nothing; it is for reading the flows.
